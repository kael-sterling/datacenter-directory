# **IdentityProvisioning PowerShell Module**

Declarative identity governance for Active Directory and Exchange-style attributes, built for the `datacenter-directory` system. This module enforces a deterministic identity model using CSV-driven configuration, unified domain settings, and multi-phase provisioning.

## **Overview**

`IdentityProvisioning` is an IaC-style identity engine that provisions and maintains AD DS users and groups using declarative configuration files. It enforces identity attributes, applies governed non-identity attributes, generates proxyAddresses across multiple domains, and maintains group membership and nesting.

The module is designed for:

- Homelab directory environments
- Multi-domain identity architectures
- Shared mailbox / department structures
- Repeatable, drift-resistant provisioning

## **Features**

### **Identity Attributes (Always Overwritten)**

Identity attributes define the user's core identity and are enforced every run:

- GivenName
- MiddleName
- Surname
- DisplayName
- sAMAccountName
- UserPrincipalName
- CanonicalName
- ManagerSamAccountName
- Department
- Title
- Company
- Initials (auto-generated)
- gecos (DisplayName)

Identity attributes are resolved through pure resolver functions and applied via the unified `Set-Attribute` writer.

### **Non-Identity Attributes (Governed)**

Non-identity attributes follow global \+ per-user overwrite rules:

- Office
- StreetAddress
- PostOfficeBox
- City
- State
- PostalCode
- Country
- TelephoneNumber
- MobileNumber

These are applied using the conditional writer `Set-IfEmpty`.

### **ProxyAddresses Generation**

ProxyAddresses are now generated by a single resolver:

```powershell
Resolve-ProxyAddresses
```

It produces:

**Primary SMTP**

```
SMTP:<sAMAccountName>@PrimaryLoginDomain
```

**Aliases**

```
smtp:<sAMAccountName>@<each secondary domain>
smtp:<CanonicalName>@PrimaryLoginDomain
smtp:<CanonicalName>@PrimaryMailDomain
smtp:<CanonicalName>@<each secondary domain>
```

The resolver guarantees:

- uniqueness
- case normalization
- deterministic ordering

Applied via:

```powershell
Set-Attribute -Attributes @{ proxyAddresses = $resolvedList }
```

### **CanonicalName Collision Handling**

1. Try `first.last`
2. If collision → `first.middleInitial.last`
3. If still collision → warn and require manual override in CSV

### **Group Management**

- Group creation
- Direct membership
- Nested membership
- ManagedBy enforcement
- ShowInGAL support
- Drift detection (membership \+ description)

### **Unified Configuration**

All identity settings live in:

```
Config\identity.json
```

Including:

- OU paths
- Domain configuration
- Secondary mail domains
- Default company
- Default country
- Global overwrite flag
- Soft manager enforcement

## **Directory Structure**

```plaintext
IdentityProvisioning\
    IdentityProvisioning.psm1
    IdentityProvisioning.psd1

    Public\
        ConvertTo-ADAttributeMap.ps1
        Invoke-IdentityProvisioning.ps1
        Resolve-ProxyAddresses.ps1
        Set-Attribute.ps1
        Set-IfEmpty.ps1
        Test-GroupDrift.ps1

    Private\
        Grant-GroupManagerUpdatePermissions.ps1
        Invoke-ConfigLoad.ps1
        Invoke-Phase.ps1
        Invoke-UserPreProvisioning.ps1
        Invoke-UserIdentityAttributes.ps1
        Invoke-UserNonIdentityAttributes.ps1
        Invoke-UserProxyAddresses.ps1
        Invoke-GroupCreation.ps1
        Invoke-GroupMembership.ps1
        Invoke-GroupNesting.ps1
        Resolve-CanonicalName.ps1
        Resolve-Initials.ps1
        Resolve-Gecos.ps1
        Write-Log.ps1

    Config\
        identity.json
        users.csv
        groups.csv
```

**Removed legacy files:**

- Build-ProxyAddresses.ps1
- Set-ProxyAddresses.ps1
- Write-ErrorWrapped.ps1

## **Usage**

### **Run full provisioning**

```powershell
Invoke-IdentityProvisioning -ConfigPath .\Config
```

### **Test group drift**

```powershell
Test-GroupDrift -ConfigPath .\Config
```

## **Philosophy**

This module treats identity as code. Every run enforces a deterministic identity model, eliminates drift, and ensures AD DS remains consistent with declarative configuration.

It is designed to be:

- Predictable
- Repeatable
- Idempotent
- Auditable
- Easy to extend
